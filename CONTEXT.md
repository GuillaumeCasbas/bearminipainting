# MiniPaint Project Context

This file contains the **validated decisions** and **technical context** for the MiniPaint project (Warhammer army painting tracker).
It should be used by all agents/sessions to maintain consistency.

---

## 🎯 Project Goal
Create a **front-end only** (MVP) application to **organize and track painting tasks** for Warhammer armies.
- **Tech Stack**: React + Zustand (state management) + TypeScript + Jest (TDD).
- **Persistence**: `localStorage` (nested structure: projects contain units).
- **Architecture**: Hexagonal (Clean Architecture) with **Core + Adapters + Ports**.

---

## 📦 Core Domain (Entities)

### **Projet (Project)**
- **Fields**:
  - `id`: UUID (string, generated by frontend).
  - `nom`: string (required).
  - `code`: string (required, **globally unique**).
  - `units`: `Unite[]` (default: `[]`).
- **Methods**:
  - `getCompletionRate(): number`:
    - Returns `100` if `units.length === 0`.
    - Otherwise: `(totalDoneTodos / totalTodos) * 100` (rounded to nearest integer).

### **Unite (Unit)**
- **Fields**:
  - `id`: UUID (string, generated by frontend).
  - `nom`: string (required).
  - `code`: string (required, **globally unique**).
  - `projectId`: string (required, references a `Projet`).
  - `todos`: `Todo[]` (6 default todos auto-created).
- **Methods**:
  - `getCompletionRate(): number`:
    - Returns `100` if `todos.length === 0`.
    - Otherwise: `(doneTodos / totalTodos) * 100` (rounded to nearest integer).
- **Default Todos**:
  Automatically added on instantiation:
  | Label         | Order | Status   |
  |---------------|-------|----------|
  | "Assembly"    | 10    | TODO     |
  | "Primer"      | 20    | TODO     |
  | "Base"        | 30    | TODO     |
  | "Effects"     | 40    | TODO     |
  | "Basecoat"    | 50    | TODO     |
  | "Varnish"     | 60    | TODO     |

### **Todo**
- **Fields**:
  - `id`: UUID (string, generated by frontend).
  - `label`: string.
  - `status`: `TodoStatus` (enum: `TODO` or `DONE`).
  - `order`: number (see ordering rules below).
- **Ordering Rules**:
  - Default todos: fixed orders (10, 20, 30...).
  - Custom todos: added **at the end** (`order = lastOrder + 10`) for MVP.
  - Future: Reordering via dedicated use case (e.g., `ReorderTodosUseCase`).

## 🔌 Ports (Interfaces)
Located in `core/ports/`.

### **ProjetRepository**
```typescript
interface ProjetRepository {
  save(projet: Projet): Promise<void>;
  findAll(): Promise<Projet[]>;
  findById(id: string): Promise<Projet | null>;
  findByCode(code: string): Promise<Projet | null>;
  delete(id: string): Promise<void>;
}
```

### **UniteRepository**
```typescript
interface UniteRepository {
  save(unite: Unite): Promise<void>;
  findById(id: string): Promise<Unite | null>;
  findByCode(code: string): Promise<Unite | null>;
  findByProjectId(projectId: string): Promise<Unite[]>;
  delete(id: string): Promise<void>;
}
```

## 🎯 Use Cases (MVP)
Located in `core/usecases/`.

| Use Case                     | Inputs               | Output       | Rules                                                                                     |
|------------------------------|----------------------|--------------|-------------------------------------------------------------------------------------------|
| `CreateProjetUseCase`        | `name`, `code`        | `Projet`     | Throws error if `code` is not unique (checked via `ProjetRepository.findByCode`).        |
| `CreateUniteUseCase`         | `name`, `code`, `projectId` | `Unite` | Throws error if `code` is not unique **OR** `projectId` does not exist.                  |
| `AddTodoToUniteUseCase`      | `uniteId`, `label`    | `Unite`      | Adds todo **at the end** (`order = lastOrder + 10`).                                         |
| `ToggleTodoStatusUseCase`    | `uniteId`, `todoId`   | `Unite`      | Toggles `TODO` ↔ `DONE` for the specified todo.                                          |

## 🏗️ Architecture
```
src/
├── core/                          # Domain Layer (100% framework-agnostic)
│   ├── entities/                 # Business entities (Projet, Unite, Todo)
│   ├── ports/                    # Interfaces (ProjetRepository, UniteRepository)
│   └── usecases/                 # Business logic (use cases)
│
├── adapters/                     # Infrastructure Layer
│   ├── persistence/              # Data access (e.g., localStorage)
│   │   ├── localstorage/         # LocalStorage implementations
│   │   │   ├── projet.repository.ts  # Implements ProjetRepository
│   │   │   └── unite.repository.ts   # Implements UniteRepository
│   └── ui/                       # UI-specific adapters (e.g., React hooks)
│
└── ui/                           # UI Layer (React + Zustand)
    ├── stores/                   # Zustand stores
    │   └── useProjetStore.ts      # Manages state, calls use cases via adapters
    └── components/               # React components
        ├── ProjectList/
        ├── ProjectDetail/
        └── UnitDetail/
```

## 💾 Persistence (localStorage)
- **Structure**: Nested (projects contain units).
  ```json
  {
    "projects": [
      {
        "id": "1",
        "name": "Space Marines",
        "code": "NMS",
        "units": [
          {
            "id": "1",
            "name": "Intercessor",
            "code": "IA-01",
            "projectId": "1",
            "todos": [...]
          }
        ]
      }
    ]
  }
  ```
- **Note**: Despite nested structure, **two separate repositories** (`ProjetRepository` + `UniteRepository`) are used for cleaner architecture and future backend migration.
- **Desynchronization Risk**: If a `Projet` is deleted, its `Unite` entries must be manually deleted (handled in use cases).

## 🧪 Testing Strategy (TDD)
- **Core Layer**: 100% TDD (Jest).
  - Write tests **before** implementing entities/usecases.
  - Mock repositories in tests (manual mocks, no external libraries).
- **UI Layer**: Tests for React components (optional for MVP).

---

## 📌 Important Notes
1. **Full Unit Code**: Computed **on-the-fly** in UI/Store as `${project.code}-${unit.code}`.
   - Not stored in `Unite` entity to avoid coupling.
2. **Language**: All code and error messages **must be in English**.
3. **Future Improvements**:
   - Backend migration (if MVP is validated).
   - Reordering todos (via `ReorderTodosUseCase`).
   - Global unit search (requires `UniteRepository.findAll()`).
   - Avoid duplicating `DEFAULT_TODOS` in tests (extract to `core/constants/default-todos.ts`).
